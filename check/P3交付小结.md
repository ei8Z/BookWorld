## 3. P3 验收（计划 §4 P3 两条）

**① 两个书 slug 并行写入互不干扰** ✅

```bash
$ export BOOK_HOME=/tmp/bw_p3v
$ bookctl books add alpha --title "阿尔法之书"
{"status": "ok", "slug": "alpha", "db_path": "/tmp/bw_p3v/books/alpha.db"}
$ bookctl --book alpha ingest --file ch13.md --chapter 13 --pov "林越" --json
{"status": "ingested", "round": 13, ...}
$ bookctl --book beta ingest --text "贝塔书的独立内容。" --chapter 1 --json
{"status": "ingested", "round": 1, ...}

$ find /tmp/bw_p3v -type f
/tmp/bw_p3v/books.json
/tmp/bw_p3v/books/alpha.db      ← 每书一个独立库文件
/tmp/bw_p3v/books/beta.db
```

**② `bookctl --book A search X` 检索不到 B 书内容** ✅

```bash
$ bookctl --book alpha search "独立内容" --json   # beta 的词
{"query": "独立内容", "mode": "fts", "hits": []}      ← 查不到 ✅
$ bookctl --book beta search "林越" --json        # alpha 的词
{"query": "林越", "mode": "fts", "hits": []}          ← 查不到 ✅
$ bookctl --book alpha search "服务器机房" --json  # 自己的词
{"query": "服务器机房", "hits": [{"id": 1, "source": "narrative", ...}]}  ← 查得到 ✅
```

HTTP 层同样验证：`?book=A`、`X-Book: A`、请求体 `{"book":"A"}` 三种选书方式都生效，
且默认书检索不到 A 书内容。

## 4. 新端点（P3-2）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| `POST` | `/api/context` | `{pov, scene, chapter, budget_chars, extra_text, book}` | ContextPack（与 CLI `context --json` 同字段） |
| `POST` | `/api/ingest` | `{file_path?, text?, volume?, chapter?, pov?, round?, no_extract?, book?}` | ingest 结果（与 CLI 同字段） |
| `GET` | `/api/search` | `?q=&k=&source=&volume=&semantic=&min_score=&book=` | `{query, mode, hits}` |
| `GET` | `/api/check` | `?range=&foreshadow_stale=&book=` | `{range, issues}` |
| `GET` | `/api/books` | — | `{books}` |

错误统一 `{"error","kind"}` + 合理状态码（usage=400 / unauthorized=401 / not_found=404 / internal=500）。

## 5. 安全（P3-3）

绑定非回环地址（`0.0.0.0` 等）时**必须**设置 `BOOK_API_TOKEN`，否则**拒绝启动**（exit 2）。
设置后所有 `/api/*` 需要 `Authorization: Bearer <token>` 或 `X-API-Token`；
静态页 `/` 免令牌（方便浏览器直接打开；它只是内嵌 UI，不含数据）。

这解决了计划里担心的"绑定 0.0.0.0 就等于把故事数据裸奔在局域网上"的问题。

## 6. 服务健壮性（P3-1）

`HTTPServer` → `ThreadingHTTPServer`（+ `daemon_threads`）。实测并发 10 个请求最大延迟 **0.05s**，
SSE 期间不再阻塞其它请求。引擎按书缓存并加锁，避免并发创建同一本书的引擎。

## 10. 独立审查与缺陷修复（第二轮）

独立 Agent 对 P3 做了对抗性验证，报出 19 项缺陷。**其中 D1 让我 P3-1 的核心承诺不成立**，
而且我的测试恰好掩盖了它。处置如下。

### 必修（已修 + 回归测试）

| # | 缺陷 | 修法 |
|---|---|---|
| **D1 高** | **HTTP 引擎缓存把 SQLite 连接绑死在创建线程**：`sqlite3.Connection` 默认 `check_same_thread=True`，而 `ThreadingHTTPServer` 每请求一线程 → 并发下 `/api/state`/`search`/`context`/`check`/`chat` 成片 500（实测 16 并发 → 14 个 500）。顺序请求因线程 id 复用而"假通过" | 引擎改为**线程本地（thread-local）缓存**：每线程持有自己的连接。实测 5 轮 × 32 并发零错误 |
| **D2 高** | macOS/Windows 大小写不敏感：`Foo`/`foo` 落到同一 inode，**多书隔离被击穿** | slug 统一 `lower()` 归一化后再校验；报错文案与行为一致（只允许小写） |
| **D7 中** | `{"book":123}` / `{"chapter":"abc"}` 直接掐断连接（客户端只见 `RemoteDisconnected`，无 `{error,kind}`） | 请求体字段先做类型校验，非法一律 400 usage |
| **D11 中** | `/api/chat` 的 SSE **永不关闭连接**（`Connection: keep-alive` 把 `close_connection` 置回 False），每连接泄漏一个线程；README 的 Kotlin 示例会挂死 | 改为响应结束即关连接；文档明确"以 `done` 事件为结束标志" |
| **D3 中** | `--book default` 与不传 `--book` 是两个互不可见的默认库 | `resolve(None)` 等价于 `resolve("default")`；不传时仍保留旧的 `book.db` 路径以免老数据"消失"，迁移会把旧库复制成 `books/default.db` |
| **D4 中** | 已存在的**空** `default.db` 永久阻断迁移 | 目标库"不存在或没有任何表"时才迁移覆盖 |
| **D5 中** | 迁移只 `copy .db`，旧库有未 checkpoint 的 WAL 时迁出的是空库 | 迁移前 `wal_checkpoint(TRUNCATE)`，并连同 `-wal`/`-shm` 一起复制 |

### 应修（已修）

| # | 缺陷 | 修法 |
|---|---|---|
| D6 | `books.json` 读-改-写无锁：20 并发 `books add` 丢 14/3/17 条 | `flock` 跨进程文件锁 + 临时文件原子 `replace` 写 |
| D8 | HTTP 校验与 CLI 不一致（`?volume=abc` → 500；`foreshadow_stale=-1` 被放过；`min_score` 静默忽略） | 统一走 `_int_param`/`_float_param`/`_str_param`，非法 → 400 usage；`min_score` 真正生效 |
| D9 | `/api/context` 类型强转（`budget_chars:true` → 1、`"abc"` → 500） | 布尔/非数字一律 400；负数预算拒绝 |
| D10 | `/api/ingest` 的 `file_path` 是**任意服务端文件读取原语**（读 `/etc/hosts` → 再 `/api/search` 取回） | 限制后缀为 `.md/.txt/.markdown/.text`；其它格式请走本地 CLI |
| D12 | legacy 端点用 `self.path` 比较：`/api/chat?book=A` 全 404 | 统一改用解析后的 `route` |
| D13 | CORS 预检只允许 `Content-Type` | 增加 `Authorization`/`X-API-Token`/`X-Book` 与 `Max-Age` |
| D14 | 设了令牌后**本机 UI 也全 401**（内嵌页面不带认证头 → 浏览器界面不可用） | 本机（回环）来源免令牌；令牌用于阻止局域网/公网裸奔。另放宽 Bearer 大小写与两侧空白 |
| D15 | `book-web` 忽略 `--host/--port`（README 的 Android 第一步无效） | 新增 `main(argv)` 真正解析参数；实测 `--host/--port/--book` 都被转发 |
| D16 | `books.json` 损坏静默变空 | 解析失败/结构异常时打印警告（不再假装"没有书"） |
| D17 | `--book ""` 静默写进共享主库 | 明确报 usage 错误 |
| D18 | `Content-Length: abc` 掐连接；巨值可占满线程 | 校验 Content-Length，非法 400，上限 32MB |
| D19 | 搬到新 `BOOK_HOME` 后 `books list` 的 db_path/exists 失真 | 路径按当前数据目录重新推导 |
