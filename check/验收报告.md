## 2. 业务流程（重点看这里）

### ★ 流程 A：互动模式（回合制，现有玩法）

```
玩家输入行动
   │
   ▼
BookEngine._prepare_context()          ← 【注意】P1 起改为提及驱动
   │  ├─ build_context(pov, scene, chapter, budget=6000, extra_text=玩家输入)
   │  │    优先级：POV主角卡 → 被提及实体 → 在场NPC → 最近3轮 → 摘要/情报
   │  │              → 未收伏笔 → 检索补充；超预算丢弃最低优先级并记入 trimmed
   │  └─ 不再全量注入 items/regions/relationships   ← 【行为变更】
   ▼
Writer 生成正文（LLM，流式）
   ▼
Extractor 抽 JSON（LLM）
   ▼
CardManager.apply() 写卡片表           ← 【注意】P2 起整体包事务，失败全回滚
   ▼
Repository.add_session() + search.index_session()
   ▼
Formatter 渲染输出
```

**你要关注**：
- 上下文从"全量卡片"改成"提及驱动"后，**写作质量是否还能保证**？这是 P1 的核心取舍，只有人能判断。
- `extra_text` 会把玩家输入算进提及范围 —— 玩家说"我去找萍萍"，赵萍就会被拉进上下文（**需你确认符合预期**）。

### ★ 流程 B：连载模式（卷章写作，与 DSH「小说家」对接）

```
小说家写出一章正文（.md）
   │
   ▼
bookctl ingest --file 第13章.md --volume 2 --chapter 13 --pov 林越 --json
   │  ├─ sha256 去重 ──→ 已存在？→ {"status":"skipped"}     ← 【幂等保证】
   │  ├─ 正文为空？ ──→ 参数错误 exit 2                       ← 【P0 审查后加的】
   │  ├─ Extractor 抽取 → CardManager.apply（事务）
   │  │     无 Key / 抽取失败 → 仍入库正文 + warning
   │  ├─ add_session(volume/chapter/pov/content_hash)
   │  ├─ index_session(ref_id = session_history.id)         ← 【ref_id 语义】
   │  └─ 标记 extracted_at（供 extract 幂等）
   ▼
bookctl context --pov 林越 --chapter 14 --budget 6000 --json
   │  ├─ 读 chapters 表 → 【本章】标题/POV/目标
   │  ├─ 读 scenes 表   → 【本章场景】+ 参与提及匹配
   │  └─ 未收伏笔只收 planted_chapter <= 14 的（不剧透）
   ▼
把 context 交给小说家写作
```

**你要关注**：
- **`ingest` 幂等按文件内容 sha256 判定**：改了稿重灌，内容变了就是新的一轮（`session_history` 多一行），**不覆盖旧章**。这是刻意设计（原文永不删），但会让"同章多版本"共存 —— 需你确认。
- `--round` 决定轮次号：`--round` > `--chapter` > 库内 `MAX(round_number)+1`。

### 流程 C：检索（写作时按需取用历史）

```
bookctl search "关键词" [--semantic] [--k N] [--source S] [--volume V] [--min-score F]
   │
   ├─ FTS 路径：真短语 → AND → 按词 OR → 单字 LIKE，bm25 排序
   │     命中标注 matched=phrase|and|or|like    ← 【让你分辨精确 vs 宽松召回】
   └─ semantic 路径：字符 n-gram 稀疏向量余弦，标注 matched=semantic
```

### 流程 D：一致性检查（长线质量保障）

```
bookctl check [--range A-B] [--foreshadow-stale N] [--deep] --json
   ├─ timeline  high : 故事内时间必须单调不减（按卷分组比较）
   ├─ state     mid  : player.hp/en 越界；npcs.is_present 与最近正文矛盾
   └─ foreshadow low : 未收伏笔埋超过 N 章（默认 30）提醒回收
```

### 流程 E：HTTP 服务（Android / EIAI 接入）

```
book-web --host 0.0.0.0 --port 8080     （必须先 export BOOK_API_TOKEN=...）
   │
   ├─ GET  /api/search?q=&k=&semantic=       → {query, mode, hits}
   ├─ POST /api/context {pov,chapter,...}    → ContextPack
   ├─ POST /api/ingest  {text|file_path,...} → ingest 结果
   ├─ GET  /api/check?range=                 → {range, issues}
   └─ POST /api/chat                         → SSE: thinking|chunk|done
```

**你要关注**：字段与 `bookctl --json` **同名**，一套解析代码两处通用。

## 4. 需要你拍板/确认的点

不是 bug，是需要人判断的取舍。每条都标了影响面。

### ① `--no-migrate` 该不该变成默认？

**现状**：任何 `bookctl` 命令（包括 `search`/`check` 这种只读操作）默认都会跑迁移，即可能改库结构。
**影响面**：真实库 `data/book.db` 就是这样被陆续加上各阶段表与列的（**数据本身始终完好**）。
**选项**：
- A. 保持现状（默认迁移，升级无感）
- B. 只读命令默认 `--no-migrate`，写命令才迁移
- C. 迁移改成显式命令（`bookctl migrate`），其余一律不动结构

### ② `data/books/default.db` 怎么处置？

**现状**：P3 迁移机制把 `data/book.db` 复制成了 `data/books/default.db`（两份内容一致，原文件保留）。
**影响面**：磁盘多一份约 220KB 复制件；好处是"默认书"有独立文件、与多书模型一致。
**选项**：
- A. 保持现状（复制，原文件作备份）
- B. `default` 直接指向 `data/book.db`，不复制

### ③ 提及驱动注入的实体范围（★ 影响写作质量）

**现状**：只有 POV 主角、**名字/别名被提到**的实体、在场实体、相关关系会进上下文。
**影响面**：如果模型需要"知道但没被提到"的设定（世界观规则、道具来历），它看不到。
**请在走查 2 时留意**：是否出现"模型明显不知道某个应该知道的设定"。
**可调项**：`alias add` 登记更多别名（提高召回）；或调整优先级策略。

### ④ `ingest` 的幂等语义

**现状**：按**文件内容 sha256** 判定。改稿重灌 = 新内容 = 新的一轮（旧章保留）。
**影响面**：同一章改 3 次会有 3 行历史；检索时旧版本也会被召回。
**请确认**：符合"原文永不删"的预期，还是希望"同章重灌就替换"。

### ⑤ `check` 的在场判定敏感度

**现状**：在场但正文一次没出现 → mid；不在场但出现 ≥2 次 → mid。单字名不参与判定。
**影响面**：阈值固定，长篇小说可能偏吵或偏静。
**可调项**：目前 `min_mentions` 是内部常量（=2），需要可加参数。

### ⑥ 术语：`ref_id` 的语义

**现状**：narrative 类检索结果的 `ref_id` = `session_history.id`（行主键），**不是轮次号**。
**影响面**：agent 拿 `ref_id` 回查要用 `session_history.id`。这是 P0 审查后改的（原来用轮次号，reindex 后会漂移）。
**请确认**：DSH 侧技能文档已按此更新。

## 5. 已知边界（不是缺陷，但影响使用预期）

| 边界 | 具体表现 | 建议 |
|---|---|---|
| **纯同义改写召不回** | 稀疏向量是字符 n-gram，实测"电脑"↔"计算机"、"妻子"↔"老婆"相似度 **0.0** | 要覆盖需接 dense 模型（`Embedder` 协议已留接口） |
| **语义检索全表算向量** | 5000 篇 × 200 字 ≈ 1.35s（FTS 0.001s），线性增长 | 万篇以内可接受；更大规模建议加向量缓存表 |
| **单字名不参与提及/在场判定** | NPC 叫「林」不会因为正文出现「林越」而被误判 | 要用单字名请 `alias add` 登记别名 |
| **无认证/多用户模型** | 本机免令牌；远程只需一个共享令牌 | 公网部署前需另做鉴权 |
| **P0 遗留：事务边界** | 在调用方 `repo.transaction()` 内调 `index_session` 会提前提交 | 当前产品路径不使用该组合 |
| **`--deep` 依赖 LLM** | 无 Key 时跳过模型深度比对（纯规则结果仍有效） | 正常降级，有 warning 说明 |
