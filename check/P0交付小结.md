## 4. 偏离计划之处（需所有者知悉）

1. **环境用 venv 而非 uv**（机器未装 uv，经确认）。
2. **3 处既有测试失败**：`test_runner.py` 的 `test_config` 原有 3 项与代码现状不符（期望相对路径 `data/book.db`/`output`、模型 `deepseek-chat`；实际为绝对路径、`deepseek-v4-pro`）。经确认改为断言现状，并按要求把模型统一为 `deepseek-flash`。**未删除、未跳过任何测试**。
3. **清理范围扩大**：计划 P0-1 只提到 `data/book.db`，实际另一个被误提交的旧库 `src/book/executor/data/book.db` 也一并移出版本库（经确认）。
4. **`ingest` 的 `round`**：计划 §5 未定义来源，实现为「`--round` > `--chapter` > 库内 `MAX(round_number)+1`」。
5. **`ingest` 的 `changes`**：CardManager 原生返回嵌套结构，CLI 层归一为 §5 示例的扁平字段（`npcs_updated`/`items_added`/`memories`/…），同时保留 `npc_names` 等明细。
6. **`context` / `check` 是 P0 基础版**：`context` 已具备预算与裁剪逻辑（P1 补别名匹配与检索增强）；`check` 返回空 `issues`（三类规则属 P2）。这是计划 §4 自己允许的。
7. **检索只索引正文，不含 POV**：`search_docs.pov` 作为可过滤元数据存储。曾试过把 POV 并进检索文本以便按角色名召回，但计划未如此规定，故回退，未擅自扩大行为。

## 7. 独立审查与缺陷修复（第二轮）

另一 Agent 对本阶段做了独立对抗性验证（穷举 1092 篇文档 × 363 查询、33 个注入式查询、
持久化强杀测试、迁移幂等、真库副本冒烟），核心机制被确认扎实（穷举零假阴性、注入零异常）。
它报出 12 项缺陷，我的处置如下。

### 已修（含回归测试）

| # | 缺陷 | 修法 |
|---|---|---|
| D1 高 | LLM 失败时诊断 print 混入 stdout，破坏 `--json` 单行契约（agent 无法 `json.loads`） | `generator.py`/`extractor.py` 所有诊断改走 stderr；并额外修正：降级文案不再冒充"未配置 Key"，抽取器用 `last_error` 把失败如实上报（此前会被误报成"未产生结构化变更"） |
| D2 中 | `CardManager.apply` 中途失败留下半截写入，`changes={}` 掩盖真实变更，索引不重建、同内容无法重跑 | `cli.run_extraction` 用 `repo.transaction()` 整体包裹 apply，失败全量回滚并在 warning 明说"已整体回滚" |
| D3 中 | narrative `ref_id` 在 ingest 用轮次号、reindex 用行主键，一次 reindex 后引用全失效 | `index_session` 改为以 `session_history.id` 为 ref_id，与 `rebuild_all` 统一（§P0-2 定义 ref_id = 来源行主键） |
| D4 中 | 同一 round 重灌覆盖旧正文索引，增量 ≠ 全量 | 由 D3 一并解决：一行一 ref_id，两版各占一条索引 |
| D6 低 | 半迁移库（缺 volume/chapter/pov 列）`rebuild_all` 仍抛 `no such column` | 按 `PRAGMA table_info` 动态拼 SQL |
| D7 低 | 单字查询顺序不符 §P0-2，`score` 恒 0.0 | 恢复"短语 → AND → OR → 单字 LIKE"顺序 |
| D8 低 | 非 `--json` 模式正文含 `[/bold]` 触发 rich `MarkupError` 退出 1 | 全部用户文本过 `rich.markup.escape` |
| D9 低 | 并发 ingest 一方 `database is locked` 退出 1 | `Repository` 增加 `PRAGMA busy_timeout=5000` |
| D10 低 | 已存在同名非唯一索引时 `CREATE UNIQUE INDEX IF NOT EXISTS` 静默失效 | 检测到非唯一同名索引则 DROP 重建（幂等，二次迁移不再动） |
| D11 低 | context 纯子串匹配把单字 NPC 名「林」误判为被提及（⊂「林越」） | 单字名不做裸子串匹配，除非 `entity_aliases` 显式登记 |
| D5 低 | 空/纯空白正文被当作成功 `ingest`：插一行长度 0 的历史、占掉 `context` 的"最近一轮"名额，且空串 sha256 是固定值（`e3b0c442…`），下一次空文件会被幂等判断报成 `already ingested`——把失败伪装成成功 | `read_input_text` 增加 `_require_text`：正文 strip 后为空则按参数错误拒绝（`{"error",…,"kind":"usage"}`、退出码 2、不写任何行）。未新增 §5 状态，未破坏契约 |

**另外发现并修复（审查者只标为"认知偏差"，实测是真 bug）**：
检索第 1 步原写作 `"甲" "乙"`，而 FTS5 里这只是 **AND 不是短语**，导致"两词都出现但不相邻"的
文档被当成精确命中。已改为真正的短语 `"甲 乙"`，并把回退补齐为
**短语 → AND → OR → 单字 LIKE** 四级；OR 回退按「词」或而不是按二元组或，
消除了跨词二元组（"AB"+"CD"→"BC"）造成的跨文档假阳性。

### 已知契约偏离（新增，需你认可）

1. **search hit 多了 `matched` 字段**（`phrase|and|or|like`）。
   §5 规定的 9 个字段一个没少、类型不变；额外字段用于让 agent 区分"精确命中"与"宽松召回"。
   §5 未写"禁止额外字段"，且 ingest 的 `changes` 本来就带附加键。
2. **单字查询 `score` 由 0.0 变为 LIKE 路径的伪分数**（不再恒 0）。
3. **narrative `ref_id` 语义**由"轮次号"改为"session_history.id"（即 §P0-2 原本的定义）。
